# Бронирование → Telegram + занятые слоты — инструкция по запуску

Я добавил в проект:
- `api/book.js` — принимает бронь, проверяет занятость, сохраняет её и шлёт сообщение в Telegram
- `api/bookings.js` — отдаёт список занятых времён на дату
- Обновил `Booking.tsx` — занятые слоты теперь подсвечиваются красным ("🔴 Занято")
  и остаются занятыми навсегда, пока вы не удалите бронь вручную из хранилища

Это серверные функции, поэтому проект нужно задеплоить на площадку, которая их
поддерживает. Ниже — самый простой бесплатный путь через **Vercel**.

## 1. Создайте Telegram-бота (5 минут)

1. В Telegram напишите **@BotFather** → `/newbot`, придумайте имя.
2. Он даст **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — сохраните.
3. Создайте группу в Telegram (или используйте существующую), добавьте туда бота.
4. Узнайте **chat_id** группы: отправьте в группу любое сообщение, затем откройте в браузере:
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
   В ответе найдите `"chat":{"id": -1001234567890, ...}` — это и есть `TELEGRAM_CHAT_ID`
   (для групп он отрицательный, это нормально).

## 2. Создайте бесплатное хранилище Upstash Redis (3 минуты)

1. Зайдите на upstash.com → Sign up → Create Database (Redis, регион ближе к Беларуси).
2. На странице базы найдите **REST API** → скопируйте `UPSTASH_REDIS_REST_URL` и
   `UPSTASH_REDIS_REST_TOKEN`.

## 3. Деплой на Vercel

1. Залейте эту папку `app/` в GitHub-репозиторий.
2. На vercel.com → New Project → импортируйте репозиторий.
3. В настройках проекта → **Environment Variables** добавьте:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`
4. Deploy. Vercel сам подхватит `api/book.js` и `api/bookings.js` как функции —
   ничего дополнительно настраивать не нужно.

## Как это работает после запуска

- Клиент выбирает дату → фронтенд запрашивает `/api/bookings?date=...` и красит
  занятые слоты красным, недоступными для клика.
- При подтверждении брони — `/api/book` ещё раз проверяет занятость (на случай
  если два человека бронировали одновременно), сохраняет бронь и шлёт вам
  сообщение в Telegram-группу с датой, временем, числом игроков, именем и телефоном.
- Слот считается занятым навсегда, пока вы не удалите запись из Redis
  (например, через консоль Upstash — вкладка Data Browser, ключ `bookings:<дата>`).

## Если хотите не через Vercel

Логика в `api/book.js` и `api/bookings.js` — обычные serverless-хендлеры
(`req, res`). Их несложно перенести под Netlify Functions или под свой Node-сервер
(Express) — просто скажите, на чём разворачиваете, и я адаптирую код под конкретную
платформу.
